# Пользовательский интерфейс Configurator

`configurator-web` — одностраничный интерфейс на React, TypeScript и Vite. Он предоставляет управление предметными
областями, типами, атрибутами и компонентами, настройку совместимости, подбор сборок и работу с сохранёнными
конфигурациями.

Общее описание системы и пользовательские сценарии находятся в [корневом README](../README.md) и
[руководстве пользователя](../docs/user/USER_GUIDE.md). Этот документ предназначен для разработчиков интерфейса.

## Требования

- Node.js 24 LTS;
- npm 11.

## Основные команды

```bash
npm ci
npm run api:generate
npm run dev
npm run check
npm run test:coverage
npm run test:delivery
```

Сервер разработки открывается на `http://127.0.0.1:5173`. Запросы `/api/*` передаются серверной части на
`http://127.0.0.1:8080` с удалением префикса `/api`.

Для проверок Playwright один раз установите браузеры:

```bash
npx playwright install
npm run test:e2e
```

Рабочая сборка создаётся в `dist/`. Полный состав проверок описан в
[`docs/testing/FRONTEND_TESTING.md`](../docs/testing/FRONTEND_TESTING.md).

## Маршруты и навигация

Основные маршруты:

- `/configurator` — подбор текущей сборки;
- `/components` — каталог компонентов;
- `/components/new` — создание компонента;
- `/components/:componentId` — карточка компонента;
- `/components/:componentId/edit` — редактирование компонента;
- `/configurations` — сохранённые конфигурации;
- `/configurations/:configurationId` — просмотр конфигурации;
- `/configurations/:configurationId/edit` — полное редактирование конфигурации;
- `/settings/types` — типы компонентов и их атрибуты;
- `/settings/attributes` — общий каталог атрибутов области;
- `/settings/compatibility/manual` — ручные связи;
- `/settings/compatibility/rules` — автоматические правила;
- `/settings/compatibility/graph` — граф совместимости;
- `/settings/domain` — параметры предметной области.

На широком экране используется боковая навигация, на телефоне — нижняя. Общая модель находится в
`src/app/layout/navigation.ts`; страницы не создают собственные варианты навигации.

Тема и язык переключаются в верхнем меню и сохраняются в `localStorage`. Текущая предметная область также выбирается
в верхней части интерфейса и определяет данные всех предметных разделов. Режим каталога «карточки/таблица» хранится
локально.

## Организация прикладного кода

Общие поставщики контекста находятся в `src/app/providers`, маршруты — в `src/app/router`, каркас приложения — в
`src/app/layout`. Предметная логика группируется в `src/features/<feature>/{api,model,ui}`.

Данные сервера хранятся через общий TanStack Query. Страницы не дублируют их в отдельном глобальном состоянии. Ключи
запросов предметных возможностей включают `domainId`, чтобы данные разных областей не смешивались.

Бизнес-формы используют React Hook Form и Zod. Подробности ошибок серверных полей преобразуются в сообщения
соответствующих элементов формы.

## Каталог атрибутов

Определение атрибута (`name`, `label`, тип данных и значения `enum`) общее для предметной области и может использоваться
несколькими типами. Обязательность и порядок задаются для каждой связи с типом отдельно.

«Убрать из типа» удаляет только связь и значения компонентов этого типа. Удаление определения из общего каталога
удаляет все его связи и значения и блокируется, если атрибут используется правилом совместимости.

## Проверка сборки

После выбора первого компонента `/configurator` запрашивает кандидатов с учётом всей текущей сборки. Основной список
содержит доступные варианты, а заблокированные кандидаты показываются отдельно с точной причиной.

Сохранение допускает связный граф разрешённых отношений: прямая связь между каждой парой компонентов не требуется.
При этом любое применимое несовпадение включённого автоматического правила блокирует сборку.

## Клиент OpenAPI

Типы, функции SDK и Fetch-клиент создаются только из `../specs/configurator-api.yaml`:

```bash
npm run api:generate
npm run api:check
```

Результат находится в `src/shared/api/generated`, хранится в репозитории и вручную не изменяется. Прикладной код
импортирует API через `@/shared/api`. Команда `api:check` входит в `npm run check` и обнаруживает расхождения со
спецификацией.

## Серверные данные и ошибки

TanStack Query подключён в общем поставщике приложения и является единственным механизмом кэширования серверных
данных. Запросы вызывают созданный SDK через `apiRequest`, который преобразует структурированные ошибки API, сетевые
сбои и неизвестные исключения в безопасный `AppError`. При вызове SDK используется `throwOnError: true`, чтобы ошибка
прошла через эту границу.

Запрос повторяется не более одного раза и только после сетевой или серверной ошибки. Изменяющие операции автоматически
не повторяются. Их ошибки показываются централизованно, а уведомление об успехе вызывает конкретный сценарий после
подтверждённого результата.

Ошибка первой загрузки отображается внутри страницы. Ошибка фонового обновления при наличии сохранённых данных
показывается уведомлением.

Общие `PageHeader`, `LoadingState`, `EmptyState`, `ErrorState` и `ServerDataState` экспортируются из `@/shared/ui`.
Сообщения отдельных полей извлекаются из `ErrorResponse.details` функцией `getFieldErrors`.

## Рабочий шлюз

`Dockerfile` выполняет `npm ci` и рабочую сборку в Node.js 24, затем копирует только `dist` в непривилегированный NGINX,
закреплённый по дайджесту. Шлюз слушает порт 8080, раздаёт SPA, поддерживает прямое открытие вложенных маршрутов и
передаёт `/api/*` внутреннему сервису `app:8080`.

Локальная сборка образа:

```bash
docker build -t configurator-web:local .
```

`npm run test:delivery` требует полный Compose на `http://127.0.0.1:8080` и проверяет настоящий API без подмены HTTP.
