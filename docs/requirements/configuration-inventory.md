# Количество компонентов и учёт остатков

Документ фиксирует действующий контракт v1.3 для каталога, конфигуратора и сохранённых конфигураций. Он расширяет
исторические требования 9.20–9.25 из [`epic-9-frontend.md`](epic-9-frontend.md).

## Каталог

- Компонент хранит неотрицательное `totalQuantity`; для существующих и новых записей без явно заданного значения оно
  равно 0.
- `allocatedQuantity` рассчитывается как сумма количеств во всех сохранённых конфигурациях с `trackInventory=true`.
- `availableQuantity = totalQuantity - allocatedQuantity`; уменьшать общее количество ниже занятого запрещено.
- Каталог и карточка показывают доступное и общее количество, форма создания и редактирования принимает общее
  количество.

## Черновик и совместимость

- Черновик содержит до 50 уникальных моделей. Для каждой модели задаётся целое количество от 1 до 999999.
- Повторное добавление модели увеличивает её количество; несколько разных моделей одного типа разрешены.
- Совместимость оценивается между уникальными моделями и остаётся независимой от количества экземпляров. Для двух и
  более моделей разрешённые отношения должны образовать связный граф, а блокирующая пара запрещает сохранение.
- Локальный формат черновика версии 2 хранит количество. Формат версии 1 читается с количеством 1 и при следующей
  записи заменяется версией 2.

## Сохранённые конфигурации

- Create/Update передают `components: [{ componentId, quantity }]` и `trackInventory`. Устаревший `componentIds`
  поддерживается отдельно: каждый ID получает количество 1; одновременная передача обоих полей недопустима.
- При `trackInventory=true` сервер блокирует затрагиваемые компоненты, учитывает собственное прежнее резервирование при
  обновлении и атомарно отклоняет запрос, если хотя бы одного количества недостаточно.
- Конфигурация без учёта остатков хранит количества, но не влияет на доступность. Изменение режима и удаление
  конфигурации соответственно создаёт или освобождает резервирование.
- Копия создаётся без учёта остатков, чтобы не резервировать состав повторно без явного решения пользователя.
- Список принимает необязательный фильтр `trackInventory`; экран предоставляет варианты «все», «с учётом количества»
  и «без учёта количества».
- JSON-экспорт использует `schemaVersion: 2` и включает количество каждой модели и `trackInventory`; импорт не входит
  в текущий контракт.

## Хранение и совместимость обновления

- Flyway V10 только добавляет колонки и индексы: `component.total_quantity = 0`,
  `configuration.track_inventory = false`, `configuration_component.quantity = 1`.
- Существующие конфигурации после миграции не занимают остатки, поэтому обновление не может неожиданно заблокировать
  каталог. Пользователь сначала задаёт общее количество, затем явно включает учёт в нужных конфигурациях.
- OpenAPI `info.version` — 1.3.0; generated backend/frontend код создаётся из спецификации и вручную не изменяется.

## Проверки

- Unit и repository tests покрывают валидацию количества, агрегирование занятости, конкурентные блокировки,
  обновление с учётом собственного резерва и запрет уменьшения общего количества ниже занятого.
- Единые local/external integration contracts проверяют create/update/delete, старый `componentIds`, фильтр режима,
  несколько моделей одного типа, недостаточный остаток и JSON schema 2.
- Frontend unit/E2E/accessibility/visual gates покрывают поля количества, режим учёта, фильтр, миграцию draft v1 и
  адаптивное отображение.
