# Заглавные изображения компонентов

Заглавным считается первое изображение галереи по порядку
`orderIndex ASC NULLS LAST, id ASC`. Действие «Сделать заглавным» передаёт полный порядок через существующую операцию
`PUT /components/{id}/images/order`: выбранное изображение перемещается в начало, взаимный порядок остальных
сохраняется. После удаления первого изображения заглавным становится следующее. Пустая галерея возвращает
`primaryImage: null`. Для архивного компонента изображения доступны только для просмотра.

`Component`, результаты множественного поиска и пересечения совместимости, а также кандидаты конфигуратора возвращают
`primaryImage`. Это вычисляемое представление, а не отдельный признак в БД. Получение списка не создаёт отдельных
запросов галерей: SQL выбирает одно изображение каждого компонента внутри основного запроса. Поле `images` по-прежнему
содержит полную галерею.

## Оригиналы и превью

- `ComponentImage.url` указывает на `/component-images/{id}/content` с исходными байтами.
- `ComponentImage.thumbnailUrl` указывает на `/component-images/{id}/thumbnail` с PNG-превью.
- Превью вписывается в 512 × 512 пикселей без обрезки и увеличения маленького изображения. Прозрачность сохраняется,
  поворот и отражение из EXIF применяются, метаданные не копируются.
- Поддерживаются декодируемые JPEG, PNG и WebP размером до 10 МиБ и 40 мегапикселей. Размеры проверяются до
  декодирования, чтение использует уменьшенную выборку пикселей.
- Для новой загрузки оригинал и превью сохраняются до записи метаданных в БД. При ошибке превью или метаданных система
  выполняет компенсирующее удаление уже записанных объектов.
- Производный объект находится в том же контейнере MinIO с ключом `<original-key>.thumbnail-v1.png`. Для старого
  изображения отсутствующее превью создаётся при первом запросе и затем сохраняется. Ошибка MinIO не подменяется
  ответом об отсутствии превью.
- Удаление изображения удаляет оригинал и превью. Контейнер MinIO остаётся закрытым: оба адреса обслуживает серверная
  часть через шлюз, перенаправлений в MinIO нет.
- Схема БД и формат резервной копии не меняются: используется существующий порядок изображений и резервирование
  контейнера MinIO.

Каталог, галерея и конфигуратор загружают уменьшенные изображения с `loading="lazy"` и `object-fit: contain`. Модальное
окно просмотра загружает оригинал. При ошибке превью показывается заглушка без автоматической загрузки тяжёлого
оригинала. После изменения изображений обновляется кэш галереи, карточки, каталога и конфигуратора только для выбранной
предметной области.

## Проверки

Общие локальные и внешние контракты проверяют одинаковое заглавное изображение в API чтения, смену порядка, удаление,
пустую галерею, настоящие размеры превью, сохранность оригинала и просмотр изображений архивного компонента.

Модульные тесты проверяют EXIF, PNG/JPEG/WebP, прозрачность, ограничение числа пикселей, обработку ошибок и кэш MinIO.
Проверки интерфейса и Playwright охватывают выбор заглавного изображения, сохранение порядка остальных, ошибки,
изоляцию кэша по областям и отсутствие запросов оригиналов в каталоге и конфигураторе.

Граница локальной доверенной эксплуатации сохраняется: объявление Bearer JWT в OpenAPI не означает наличия действующей
аутентификации. Возможность не разрешает развёртывание в локальной сети, интернете или на общем сервере.
