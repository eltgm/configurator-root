# Руководство пользователя Configurator

Это руководство помогает впервые познакомиться с Configurator, подготовить собственный каталог компонентов, настроить
совместимость и сохранить первую сборку. Для работы с интерфейсом знания программирования не нужны.

## Что представляет собой система

Configurator хранит сведения о компонентах и помогает составлять из них допустимые наборы. Система не ограничена
конкретной отраслью: одинаковая модель подходит для компьютерных комплектующих, оборудования, модулей изделия,
элементов рабочего места и других составных объектов.

Основные понятия:

| Понятие                | Назначение                                                       | Пример                                 |
| ---------------------- | ---------------------------------------------------------------- | -------------------------------------- |
| Предметная область     | Изолированный каталог со своими типами, компонентами и правилами | «Сборка ПК»                            |
| Тип компонента         | Группа однотипных позиций                                        | «Процессор»                            |
| Атрибут                | Характеристика, которой описываются компоненты                   | «Сокет» или «Объём памяти»             |
| Компонент              | Модель каталога с общим, занятым и доступным количеством         | «Процессор X», 12 экземпляров          |
| Ручная связь           | Явное подтверждение совместимости пары компонентов               | Процессор подходит к материнской плате |
| Автоматическое правило | Проверка значений атрибутов двух компонентов                     | Значения сокета должны совпадать       |
| Сборка                 | Выбранные модели и количество их экземпляров                     | Процессор, плата и две планки памяти   |
| Конфигурация           | Сохранённая сборка, которая может учитывать остатки              | «Домашний компьютер»                   |

Данные разных предметных областей не смешиваются. Выбранная область отображается в верхней части интерфейса и
определяет содержимое всех основных разделов.

## Поддерживаемый способ работы

Приложение предназначено для одного доверенного пользователя на локальном компьютере. Оно открывается по адресу
<http://127.0.0.1:8080> и не должно публиковаться в локальной сети или интернете. Аутентификация и разграничение прав
пока не реализованы.

Установка готового пакета описана в [руководстве по локальной поставке](../release/LOCAL_DELIVERY.md). После запуска
пакета дальнейшая работа выполняется в браузере.

## Первое знакомство

При первом открытии система предложит создать предметную область. Есть два пути.

### Демонстрационная область

Нажмите «Создать демо „Сборка ПК“», если хотите сразу увидеть заполненный пример. Система добавит типы, атрибуты,
компоненты и правила совместимости. После этого можно без предварительной настройки открыть «Конфигуратор» и изучить
подбор вариантов.

Демонстрационная область подходит для знакомства, проверки установки и изучения устройства данных. Её можно изменять
так же, как обычную область.

### Пустая область

Нажмите «Новая область», если хотите сразу создать собственный каталог. Укажите понятное название и краткое описание.
После создания последовательно настройте типы, атрибуты, компоненты и совместимость.

Новые области и переключение между ними доступны через выбор предметной области в верхней части интерфейса. Управление
названием, описанием и удалением текущей области находится в разделе «Настройка → Параметры области».

## Навигация и несохранённые изменения

На узком экране пункт «Настройка» открывает панель со всеми разделами настроек. Пункт «Помощь» доступен в навигации
и в меню настроек интерфейса; там описаны последовательность работы, учёт количества и условия сохранения сборки.

При закрытии изменённой формы приложение предлагает продолжить заполнение или отбросить изменения. Это относится
также к Escape, отмене, переходу назад и смене области. При отмене ухода поля сохраняются. При закрытии вкладки
предупреждение показывает сам браузер. Формы не сохраняются между запусками; автоматическое сохранение относится
к черновику сборки в конфигураторе.

## Рекомендуемый порядок настройки каталога

Для новой предметной области удобнее придерживаться следующего порядка:

1. определить типы компонентов;
2. создать общий каталог атрибутов;
3. подключить атрибуты к нужным типам;
4. добавить компоненты, их общее количество и изображения;
5. задать ручные связи и автоматические правила;
6. проверить результат в конфигураторе;
7. сохранить первую конфигурацию.

Такой порядок уменьшает число возвратов к уже заполненным формам.

## Типы компонентов

Откройте «Настройка → Типы и атрибуты» и нажмите «Новый тип».

Для типа задаются:

- название для пользователя;
- необязательный короткий код;
- описание;
- индекс порядка: типы с меньшим значением показываются раньше.

Примеры типов для компьютерной области: «Процессор», «Материнская плата», «Оперативная память», «Видеокарта».

Тип нельзя удалить, пока с ним связаны атрибуты или компоненты. Сначала удалите или перенесите зависимые данные.

## Атрибуты

Атрибуты образуют общий каталог предметной области. Одно определение можно подключить к нескольким типам. Например,
атрибут «Производитель» не нужно создавать отдельно для процессоров и материнских плат.

### Создание общего атрибута

1. Откройте «Настройка → Атрибуты».
2. Нажмите «Новый атрибут».
3. Укажите название для пользователя.
4. Проверьте автоматически предложенное системное имя.
5. Выберите тип данных: текст, число, «да/нет» или список допустимых значений.
6. Для списка добавьте все разрешённые значения.
7. Сохраните атрибут.

Системное имя используется в API и правилах совместимости. Оно уникально в пределах области с учётом регистра. Если
система сообщает, что такое имя уже занято, подключите существующий атрибут вместо создания дубликата.

### Подключение атрибута к типу

1. Откройте «Настройка → Типы и атрибуты».
2. Выберите тип компонента.
3. Нажмите «Добавить атрибут → Использовать существующий».
4. Выберите определение из общего каталога.
5. Укажите, обязателен ли атрибут для компонентов этого типа, и задайте его порядок.

Обязательность и порядок хранятся отдельно для каждой связи с типом. Один и тот же атрибут может быть обязательным для
одного типа и необязательным для другого.

Команда «Убрать из типа» сохраняет определение в общем каталоге, но удаляет его значения у компонентов выбранного
типа. Удаление атрибута из каталога удаляет все его связи и значения во всей области. Атрибут, используемый правилом
совместимости, сначала нужно убрать из правила.

## Компоненты

Откройте раздел «Компоненты» и нажмите «Создать компонент».

1. Выберите тип.
2. Укажите название, необязательный артикул, описание и общее количество экземпляров.
3. Заполните обязательные и нужные дополнительные атрибуты.
4. Сохраните компонент.
5. При необходимости откройте его карточку и добавьте изображения.

Каталог поддерживает поиск, фильтрацию по типу и состоянию, а также отображение карточками или таблицей. Выбранный вид
запоминается в браузере.

Общее количество — это число физических экземпляров модели. Карточка и каталог также показывают, сколько экземпляров
занято конфигурациями с включённым учётом количества и сколько осталось доступно. Новая модель по умолчанию имеет
нулевой остаток. Общее количество нельзя уменьшить ниже уже занятого; сначала измените или удалите учитывающие остатки
конфигурации.

Фильтры и страница каталога сохраняются в адресе. «К каталогу» из карточки возвращает к последнему списку этой
области; смена области сбрасывает параметры списка. Идентификатор области в адрес не добавляется.

### Изображения

В карточке компонента можно загрузить несколько изображений, изменить их порядок и удалить ненужные. Первое изображение
считается заглавным и используется в каталоге и конфигураторе. Команда «Сделать заглавным» перемещает выбранное
изображение в начало галереи.

Максимальный размер одного файла — 10 МБ. Поддерживаемый формат проверяется при загрузке. Для списков система создаёт
уменьшенные PNG-копии, а при увеличении показывает оригинал.

### Архив

Архивирование скрывает компонент из обычного подбора, но сохраняет его и связанные данные. В каталоге можно включить
показ архивных записей и восстановить компонент.

Архивный компонент, оставшийся в ранее сохранённой конфигурации, отображается как архивный. Перед сохранением изменённой
конфигурации его следует заменить или удалить из состава.

## Ручная совместимость

Ручная связь подходит для отдельных пар, совместимость которых известна заранее и не требует общего правила.

1. Откройте «Настройка → Ручная совместимость».
2. Нажмите «Новая ручная связь».
3. Выберите два компонента.
4. При необходимости добавьте пояснение.
5. Сохраните связь.

Связь действует в обе стороны. Её можно найти через поиск и удалить, если условия изменились.

## Автоматические правила

Автоматическое правило сравнивает атрибуты компонентов заданных типов. Оно удобно, когда одна закономерность должна
применяться ко всему каталогу.

Пример: процессор и материнская плата совместимы, если значения атрибута «Сокет» совпадают.

1. Откройте «Настройка → Автоматические правила».
2. Нажмите «Новое правило».
3. Задайте название и выберите типы компонентов.
4. Добавьте одно или несколько условий сравнения их атрибутов.
5. Проверьте, включено ли правило.
6. Сохраните его.

Правило можно открыть, полностью изменить, временно отключить или удалить. Если применимое включённое правило не
выполняется, пара считается несовместимой и блокирует добавление или сохранение сборки. Конфигуратор показывает
названия правил, вызвавших запрет.

## Граф совместимости

Раздел «Настройка → Граф совместимости» показывает компоненты и связи между ними. Он помогает:

- проверить, какие связи уже заданы;
- увидеть изолированные части каталога;
- найти путь совместимости через промежуточные компоненты;
- перейти к интересующему компоненту.

Граф дополняет, но не заменяет проверку в конфигураторе: итоговая допустимость сборки рассчитывается сервером с учётом
ручных связей и автоматических правил.

## Сборка в конфигураторе

Откройте раздел «Конфигуратор». Слева или сверху, в зависимости от ширины экрана, находится список доступных
компонентов, рядом — текущая сборка.

### Начало сборки

1. При необходимости включите «Учитывать количество компонентов». По умолчанию чекбокс выключен.
2. Найдите первый компонент по названию или типу.
3. Нажмите «Добавить».
4. После первого выбора система начнёт оценивать остальные варианты относительно текущего состава.
5. Добавляйте нужные модели; во включённом режиме задавайте количество каждой из них.

При включённом учёте повторное добавление уже выбранной модели увеличивает её количество. UI показывает доступное и
выбранное количество, а модель с нулевым остатком оставляет видимой, но блокирует её добавление. В одну сборку можно
включить несколько разных моделей одного типа; лимит 50 относится к числу уникальных моделей, а количество одной
модели может быть от 1 до 999999. Выключение чекбокса скрывает сведения о количестве, но не сбрасывает выбор.

Черновик автоматически сохраняется в браузере отдельно для каждой предметной области. Он восстанавливается после
перезагрузки страницы. Это локальный черновик, а не сохранённая конфигурация: при очистке данных браузера он исчезнет.

### Доступные и заблокированные варианты

Основной список содержит варианты, которые имеют подтверждённую связь хотя бы с одной позицией сборки и не нарушают
обязательные правила. Заблокированные варианты показываются отдельно с объяснением конфликта.

Переключатель «Показать варианты через промежуточные компоненты» разрешает показывать компоненты, достижимые через цепочку связей.
При этом перед сохранением сервер всё равно проверяет итоговый состав по прямым отношениям выбранных элементов и
связности всей сборки.

Карточка варианта показывает до трёх характеристик в порядке, заданном для типа. «Быстрый просмотр» открывает
панель с описанием, остатками и всеми характеристиками; закрытие панели возвращает к подбору. Поиск и фильтр типа
сохраняются при изменении состава. Список заблокированных моделей можно раскрывать кнопкой «Показать ещё».

На телефоне варианты расположены перед составом сборки; кнопки «Выбрать компоненты» и «Состав сборки» помогают
перейти к нужной части страницы. Поиск через промежуточные компоненты находится в «Дополнительных параметрах».

### Условия сохранения

Сборку можно сохранить, когда:

- загрузка всех компонентов завершена;
- в составе нет архивных или недоступных позиций;
- включённые автоматические правила не запрещают ни одну применимую пару;
- все компоненты соединены путями подтверждённых связей.
- при включённом учёте выбранное количество не превышает доступное.

Прямая связь между каждой парой не требуется. Достаточно, чтобы вся сборка представляла один связный граф. Если
условие не выполнено, блок проверки сообщает причину и показывает проблемные пары.

## Сохранённые конфигурации

Поиск по названию работает по всем сохранённым конфигурациям выбранной области, независимо от страницы. Можно
сортировать по названию или времени создания в обе стороны и сочетать поиск с фильтром учёта остатков. Карточки
показывают первые три позиции состава; кнопка «Ещё» раскрывает остальные.

Когда сборка прошла проверку, нажмите «Сохранить конфигурацию», укажите название и необязательное описание. Режим учёта
выбирается заранее, в начале сборки, а не в окне сохранения. Если он включён, интерфейс заранее блокирует сохранение
при дефиците, после чего сервер повторно проверяет остатки и сохраняет конфигурацию атомарно.

Без этого переключателя количества остаются частью состава, но не уменьшают доступный остаток. Существующие до
обновления конфигурации именно такие. Включить или выключить учёт можно позднее при редактировании, если текущих
остатков достаточно.

В разделе «Конфигурации» доступны:

- просмотр состава и сведений о конфигурации;
- полное редактирование состава, названия и описания;
- изменение количества и режима учёта остатков;
- фильтрация списка по конфигурациям с учётом количества и без него;
- создание независимой копии;
- выгрузка данных в JSON;
- безвозвратное удаление.

Редактирование использует те же правила проверки, что и новая сборка. Несохранённые изменения защищены предупреждением
при попытке уйти со страницы или сменить предметную область.

Копия не связана с исходной конфигурацией: последующие изменения одной записи не влияют на другую. Она наследует режим
учёта исходной конфигурации; если свободного остатка для второй записи недостаточно, кнопка создания копии будет
заблокирована. Выгрузка JSON включает количества и режим учёта, создаёт файл для просмотра или передачи данных, но
обратный импорт этого файла в текущей версии не предусмотрен.

## Удаление предметной области

Удаление области выполняется в «Настройка → Параметры области» и требует точного ввода её названия. Это необратимое
действие.

Наличие хотя бы одной сохранённой конфигурации блокирует удаление. Сначала удалите все конфигурации области. После
подтверждения система удалит типы, атрибуты, активные и архивные компоненты, значения, изображения, правила и связи.

Записи об удалении файлов изображений сохраняются в очереди, поэтому временная недоступность MinIO не отменяет удаление
данных из PostgreSQL. Файлы будут очищены после восстановления доступа к хранилищу.

## Настройки интерфейса

В меню интерфейса можно выбрать:

- русский или английский язык;
- светлую, тёмную или системную тему;
- вид каталога компонентов: карточки или таблица.

Выбор сохраняется в браузере. На широком экране основные разделы находятся в боковой панели, на телефоне — в нижней
панели, а дополнительные настройки открываются через раздел «Настройка».

## Резервное копирование и обновление

Перед важными изменениями данных и обновлением приложения создавайте резервную копию командой `Backup` из каталога
пользовательского пакета. Команда `Update` делает обязательную копию автоматически перед загрузкой новой стабильной
версии. Команда `Restore` проверяет контрольные суммы и перед восстановлением сохраняет страховочную копию текущего
состояния.

Неудачное обновление или восстановление намеренно оставляет приложение остановленным. Исправьте причину и повторите
операцию либо восстановите последнюю рабочую копию. Файлы резервных копий не зашифрованы — храните их в защищённом
месте.

Подробные команды и порядок полного удаления приведены в
[руководстве по локальной поставке](../release/LOCAL_DELIVERY.md).

## Если возникла проблема

1. Убедитесь, что Docker Desktop запущен.
2. Повторите действие после обновления страницы.
3. Если приложение недоступно, выполните `Stop`, затем `Start`.
4. Сохраните версию пакета, сведения об ОС и безопасный фрагмент журнала из каталога `logs`.
5. Следуйте [правилам обращения за поддержкой](../../SUPPORT.md).

Не публикуйте пароли, ключи, резервные копии и другие личные данные. Сведения об уязвимостях передавайте только
приватным способом, указанным в [политике безопасности](../../SECURITY.md).
