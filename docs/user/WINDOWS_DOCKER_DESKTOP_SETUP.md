# Установка Docker Desktop в Windows 10 и Windows 11

Это руководство помогает подготовить обычный домашний или рабочий компьютер к запуску готового пакета Configurator.
Оно рассчитано на пользователя, который раньше не работал с Docker, WSL или BIOS/UEFI.

После выполнения всех шагов на компьютере будут:

- включена аппаратная виртуализация;
- установлена и обновлена подсистема WSL 2;
- установлен и запущен Docker Desktop с движком WSL 2;
- доступны команды `docker` и `docker compose`;
- готов к запуску Windows-пакет Configurator.

Инструкция и требования проверены 9 сентября 2026 года. Интерфейс Windows, BIOS/UEFI и Docker Desktop может немного
отличаться в зависимости от версии и производителя компьютера. Если текущие требования на официальном сайте Docker
строже приведённых ниже, ориентируйтесь на актуальные требования Docker.

> [!IMPORTANT]
> Configurator предназначен только для локального использования одним доверенным пользователем. В приложении пока нет
> действующей аутентификации. Не публикуйте его в локальную сеть или интернет и не меняйте адрес `127.0.0.1` на
> `0.0.0.0`.

## Короткий маршрут

Если виртуализация уже включена и WSL не установлен, весь процесс выглядит так:

1. Проверить Windows и виртуализацию.
2. При необходимости включить виртуализацию в BIOS/UEFI.
3. Открыть PowerShell от имени администратора и выполнить:

   ```powershell
   wsl --install --no-distribution
   ```

4. Перезагрузить компьютер.
5. Выполнить `wsl --update`.
6. Скачать и установить Docker Desktop for Windows x86_64 с официального сайта.
7. Запустить Docker Desktop и дождаться готовности движка.
8. Проверить `docker version` и `docker compose version`.
9. Распаковать пакет Configurator и запустить `Start.cmd`.

Если команда не сработала или название пункта отличается, используйте подробные разделы ниже.

## 1. Что именно устанавливается

### Аппаратная виртуализация

Это возможность процессора запускать изолированную виртуальную среду. У Intel она обычно называется Intel
Virtualization Technology, VT-x или VMX, у AMD — AMD-V или SVM Mode. На многих новых компьютерах она уже включена.

### WSL 2

Windows Subsystem for Linux 2, или WSL 2, — системный компонент Microsoft с ядром Linux. Docker Desktop использует
его для запуска Linux-контейнеров. Устанавливать Ubuntu или другую пользовательскую Linux-систему для Configurator не
нужно: Docker Desktop создаёт и обслуживает собственную среду WSL.

### Docker Desktop

Docker Desktop загружает и запускает контейнеры Configurator, PostgreSQL, MinIO и локального веб-шлюза. JDK, Gradle,
Node.js, npm и Git для готового пакета не нужны.

Для Configurator выбран движок WSL 2 и Linux-контейнеры. Компоненты Hyper-V и Windows Containers не требуются.

## 2. Что понадобится до начала

- компьютер с 64-разрядным процессором x86-64 и поддержкой виртуализации;
- Windows 10 или Windows 11 x86-64 с установленными обновлениями;
- не менее 8 ГБ оперативной памяти по требованиям Docker Desktop;
- свободное место на системном диске для Docker Desktop, образов и данных приложения;
- устойчивое подключение к интернету для установки и первого запуска;
- возможность перезагрузить компьютер;
- права администратора для первого включения WSL 2 и компонентов Windows.

Практически удобно иметь не менее 20 ГБ свободного места с запасом. Это не фиксированный системный минимум: занятое
место будет расти вместе с образами, резервными копиями и данными Configurator.

> [!NOTE]
> Docker Desktop имеет собственные лицензионные условия. Личное использование, обучение, некоммерческие проекты и
> малый бизнес обычно относятся к бесплатным сценариям. Для крупных организаций, государственных учреждений и части
> коммерческих сценариев может требоваться платная подписка. Перед установкой на рабочий компьютер уточните правила у
> своей организации и прочитайте актуальные условия Docker.

### Поддерживаемая версия Windows

1. Нажмите `Win + R`.
2. Введите `winver`.
3. Нажмите Enter.
4. Запишите выпуск, версию и номер сборки Windows.

На дату проверки официальная документация Docker для WSL 2 backend указывает:

| Система    | Указанная Docker минимальная версия  |
| ---------- | ------------------------------------ |
| Windows 10 | 64-bit, 22H2, сборка 19045           |
| Windows 11 | 64-bit, 23H2, сборка 22631 или новее |

Docker поддерживает только выпуски Windows, которые находятся в периоде обслуживания Microsoft. Установите все
доступные накопительные обновления. На Windows 10 откройте «Параметры → Обновление и безопасность → Центр обновления
Windows», на Windows 11 — «Параметры → Центр обновления Windows».

Пакет Configurator для Windows собран для x86-64. Версия Docker Desktop for Windows Arm находится в другом статусе и
для этого пакета не поддерживается.

Чтобы проверить архитектуру и память:

1. Нажмите `Win + I`.
2. Откройте «Система → О системе» в Windows 11 или «Система → О системе» / «Сведения о системе» в Windows 10.
3. В строке «Тип системы» должно быть указано «64-разрядная операционная система, процессор x64».
4. В строке «Оперативная память» должно быть не менее 8 ГБ.

Чтобы проверить место на диске, откройте Проводник сочетанием `Win + E`, выберите «Этот компьютер» и посмотрите
свободное место на диске `C:`. После обновления Windows обязательно выполните предложенную системой перезагрузку до
установки WSL.

### Домашний или рабочий компьютер

На личном компьютере вы обычно можете выполнить все шаги самостоятельно. На устройстве организации могут быть
запрещены изменение BIOS/UEFI, включение компонентов Windows, Microsoft Store или установка приложений. Не обходите
такие ограничения: обратитесь к системному администратору и покажите ему этот документ.

Если Windows работает внутри VMware, VirtualBox, Parallels, VDI или другой виртуальной машины, нужна вложенная
виртуализация на физическом хосте. Обычная установка Docker Desktop внутри виртуальной машины может не поддерживаться
лицензией или инфраструктурой организации.

## 3. Проверка виртуализации

Сначала проверьте текущее состояние. Если виртуализация уже включена, входить в BIOS/UEFI не нужно.

1. Нажмите `Ctrl + Shift + Esc`.
2. Если открылось компактное окно «Диспетчер задач», нажмите «Подробнее».
3. Откройте вкладку «Производительность».
4. Выберите «ЦП» или «CPU».
5. Найдите строку «Виртуализация» или `Virtualization`.

Возможны два результата:

- «Включено» / `Enabled` — переходите к разделу [Установка WSL 2](#5-установка-wsl-2);
- «Отключено» / `Disabled` — включите виртуализацию в BIOS/UEFI по следующему разделу.

Дополнительная проверка оборудования:

1. Откройте меню «Пуск».
2. Введите `PowerShell` и откройте найденное приложение.
3. Выполните:

   ```powershell
   systeminfo.exe
   ```

4. В конце отчёта найдите раздел «Требования Hyper-V» / `Hyper-V Requirements`.

Значение «Да» / `Yes` у аппаратной виртуализации и SLAT означает, что соответствующая возможность доступна. Если
Windows уже запустила гипервизор, вместо отдельных строк может быть сообщение о том, что гипервизор обнаружен. Это
тоже нормальный результат.

## 4. Включение виртуализации в BIOS/UEFI

BIOS/UEFI запускается до Windows и управляет базовыми настройками компьютера. Внешний вид и названия пунктов различаются
даже у моделей одного производителя.

> [!CAUTION]
> Меняйте только параметр виртуализации. Не отключайте Secure Boot, TPM, шифрование диска, режим UEFI и не изменяйте
> порядок загрузки, режим накопителя или напряжения процессора. Ошибочные изменения могут помешать запуску Windows.

### 4.1. Подготовьтесь к перезагрузке

1. Сохраните документы и закройте программы.
2. Если используется шифрование устройства или BitLocker, заранее убедитесь, что доступен 48-значный ключ
   восстановления. Изменение настроек оборудования или прошивки иногда вызывает запрос этого ключа при следующем
   запуске. Инструкция Microsoft: [поиск ключа восстановления BitLocker](https://support.microsoft.com/windows/finding-your-bitlocker-recovery-key-in-windows-6b71ad27-0b89-ea08-f143-056f5ab347d6).
3. Узнайте производителя и модель: нажмите `Win + R`, введите `msinfo32`, нажмите Enter и запишите значения
   «Изготовитель» и «Модель».
4. Желательно открыть эту инструкцию или страницу поддержки производителя на телефоне: после перезагрузки браузер на
   компьютере будет недоступен.

### 4.2. Войдите в UEFI из Windows

Для Windows 11:

1. Откройте «Пуск → Параметры → Система → Восстановление».
2. В разделе «Расширенные параметры запуска» нажмите «Перезагрузить сейчас».
3. Подтвердите перезагрузку.

Для Windows 10:

1. Откройте «Пуск → Параметры → Обновление и безопасность → Восстановление».
2. В разделе «Особые варианты загрузки» нажмите «Перезагрузить сейчас».

После перезагрузки для обеих систем:

1. Выберите «Поиск и устранение неисправностей».
2. Выберите «Дополнительные параметры».
3. Выберите «Параметры встроенного ПО UEFI».
4. Нажмите «Перезагрузить».

Если пункта «Параметры встроенного ПО UEFI» нет, используйте клавишу входа при включении компьютера или инструкцию
производителя.

### 4.3. Альтернативный вход клавишей

Полностью выключите компьютер. Включите его и сразу несколько раз нажимайте клавишу входа, пока не появится меню
настройки. Часто используются:

| Производитель | Частые клавиши                        |
| ------------- | ------------------------------------- |
| Acer          | `F2`, иногда `Delete`                 |
| ASUS          | `F2` для ноутбука, `Delete` для платы |
| Dell          | `F2`                                  |
| HP            | `Esc`, затем `F10`                    |
| Lenovo        | `F1`, `F2` или кнопка Novo            |
| MSI/Gigabyte  | `Delete`                              |

Точная клавиша зависит от модели. На ноутбуке может потребоваться `Fn + F2` вместо `F2`. Если появляется Windows,
выключите компьютер и повторите попытку, начиная нажимать клавишу сразу после кнопки питания.

### 4.4. Найдите нужный параметр

Параметр обычно расположен в разделах `Advanced`, `Advanced Mode`, `CPU Configuration`, `Processor`, `Security` или
`System Configuration`.

Для процессора Intel ищите одно из названий:

- `Intel Virtualization Technology`;
- `Intel (VMX) Virtualization Technology`;
- `Intel VT-x`;
- `Virtualization Technology`.

Для процессора AMD ищите:

- `SVM Mode`;
- `AMD-V`;
- `AMD Virtualization`;
- `Secure Virtual Machine`.

Установите найденный параметр в `Enabled`.

`VT-d`, `IOMMU`, `Intel TXT`, `Trusted Execution` и `SR-IOV` — другие функции. Для обычного запуска Configurator через
WSL 2 менять их, как правило, не требуется. Если производитель вашей модели прямо требует дополнительную настройку,
следуйте его официальной инструкции.

Официальные инструкции для распространённых производителей собраны на странице Microsoft
[«Включение виртуализации в Windows»](https://support.microsoft.com/en-us/windows/experience/enable-virtualization-on-windows).
Прямые страницы производителей:

- [Acer](https://community.acer.com/en/kb/articles/14750);
- [ASUS, AMD](https://www.asus.com/support/faq/1043992/);
- [ASUS, Intel для системных плат](https://www.asus.com/support/faq/1043786/);
- [ASUS, Intel для ноутбуков](https://www.asus.com/support/faq/1043181/);
- [Dell](https://www.dell.com/support/kbdoc/000195978/);
- [Lenovo](https://support.lenovo.com/solutions/ht500006).

Для HP и отсутствующих в списке моделей найдите инструкцию по точному номеру модели на сайте производителя. Не
используйте случайные программы, обещающие включить виртуализацию из Windows: этот параметр меняется в прошивке.

### 4.5. Сохраните настройку

1. Выберите `Save & Exit`, `Save Changes and Exit` или нажмите `F10`, если эта клавиша указана на экране.
2. Подтвердите сохранение.
3. Дождитесь обычного запуска Windows.
4. Повторите проверку в «Диспетчер задач → Производительность → ЦП».

Если виртуализация всё ещё отображается как отключённая, ещё раз проверьте настройку по инструкции производителя. На
рабочем компьютере обратитесь к администратору; прошивка может быть защищена паролем или политикой организации.

## 5. Установка WSL 2

### 5.1. Рекомендуемый способ

Docker Desktop не требует отдельной Ubuntu, поэтому установим WSL без пользовательского Linux-дистрибутива.

1. Откройте меню «Пуск».
2. Введите `PowerShell`.
3. Нажмите правой кнопкой мыши по Windows PowerShell и выберите «Запуск от имени администратора».
4. Разрешите изменение устройства в окне контроля учётных записей.
5. Выполните:

   ```powershell
   wsl --install --no-distribution
   ```

6. Дождитесь завершения. Не закрывайте окно во время установки.
7. Перезагрузите компьютер, даже если Windows не попросила об этом явно.

Если команда сообщает, что WSL уже установлен, это не ошибка. После перезагрузки перейдите к обновлению WSL.

Если параметр `--no-distribution` не распознан, сначала установите все обновления Windows. Затем используйте ручной
способ ниже. Команда `wsl --install` без этого параметра также включает WSL, но дополнительно устанавливает Ubuntu,
которая Configurator не нужна.

### 5.2. Обновите WSL

После перезагрузки откройте обычный PowerShell и выполните:

```powershell
wsl --update
```

Затем установите WSL 2 версией по умолчанию для возможных новых сред:

```powershell
wsl --set-default-version 2
```

На дату проверки Docker Desktop требует WSL не ниже 2.1.5 и рекомендует актуальную версию.

### 5.3. Ручное включение через интерфейс Windows

Этот способ используйте, если `wsl --install --no-distribution` не работает.

1. Откройте меню «Пуск».
2. Начните вводить «Включение или отключение компонентов Windows» и откройте найденный элемент панели управления.
3. Установите флажки:
   - «Платформа виртуальной машины» / `Virtual Machine Platform`;
   - «Подсистема Windows для Linux» / `Windows Subsystem for Linux`.
4. Нажмите «ОК».
5. Дождитесь применения изменений.
6. Нажмите «Перезагрузить сейчас».
7. После перезагрузки снова откройте PowerShell и выполните `wsl --update`.

Не включайте специально `Hyper-V`, `Контейнеры` / `Containers` и `Windows Hypervisor Platform`: выбранному сценарию
WSL 2 с Linux-контейнерами они не нужны. Если эти компоненты уже включены другой программой или политикой Windows, не
отключайте их без понимания последствий.

### 5.4. Ручное включение командами DISM

Если графический интерфейс недоступен, откройте PowerShell от имени администратора и по очереди выполните:

```powershell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
```

После успешного завершения обеих команд перезагрузите компьютер и выполните:

```powershell
wsl --update
wsl --set-default-version 2
```

### 5.5. Проверка WSL

В PowerShell выполните:

```powershell
wsl --version
wsl --status
wsl --list --verbose
```

Проверьте следующее:

- `wsl --version` показывает номера версии WSL и ядра;
- версия WSL не ниже 2.1.5;
- версия по умолчанию в `wsl --status` равна 2;
- команды завершаются без кодов ошибок.

До первого запуска Docker список `wsl --list --verbose` может быть пустым. Это нормально: отдельный Linux-дистрибутив
для Configurator не нужен. После запуска Docker Desktop в списке может появиться управляемая Docker среда.

Если `wsl --version` не показывает сведения о версии, установлен старый встроенный вариант WSL. Выполните
`wsl --update`. Если Microsoft Store заблокирован политикой организации, используйте официальный MSI из раздела
Assets на странице [выпусков WSL](https://github.com/microsoft/WSL/releases) или обратитесь к администратору.

## 6. Установка Docker Desktop

### 6.1. Скачайте официальный установщик

1. Откройте официальную страницу
   [Install Docker Desktop on Windows](https://docs.docker.com/desktop/setup/install/windows-install/).
2. Выберите `Docker Desktop for Windows - x86_64`.
3. Сохраните `Docker Desktop Installer.exe`.

Не скачивайте Docker Desktop с каталогов программ, файлообменников и сторонних сайтов.

При желании проверьте цифровую подпись:

1. Нажмите правой кнопкой по установщику и выберите «Свойства».
2. Откройте вкладку «Цифровые подписи».
3. Убедитесь, что подпись действительна и относится к Docker.

### 6.2. Запустите установку

1. Дважды щёлкните `Docker Desktop Installer.exe`.
2. Если установщик предлагает режим установки, выберите установку для текущего пользователя (`per-user`). Это
   рекомендуемый Docker режим для большинства пользователей и WSL 2 backend.
3. Если показан выбор backend, выберите `Use WSL 2 instead of Hyper-V`.
4. Не выбирайте Windows containers: Configurator использует Linux-контейнеры.
5. Дождитесь копирования файлов и завершите установку.

Установка WSL 2 впервые требует прав администратора. Сам Docker Desktop в рекомендуемом режиме текущего пользователя
может устанавливаться и обновляться без них. Режим «для всех пользователей» нужен только при отдельном требовании
организации или для функций Hyper-V/Windows containers, которые Configurator не использует.

### 6.3. Первый запуск

1. Откройте меню «Пуск».
2. Найдите и запустите Docker Desktop.
3. Прочитайте Docker Subscription Service Agreement и продолжайте только после принятия условий.
4. Если предлагается вход в Docker Hub, для запуска публичных образов Configurator он не требуется. Пропустите вход,
   если интерфейс позволяет и у вашей организации нет другого правила.
5. Дождитесь сообщения о готовности движка. Первый запуск может занять несколько минут.

Не закрывайте Docker Desktop крестиком во время первого запуска. В зависимости от настроек окно может закрыться, но
само приложение останется в системном трее рядом с часами.

### 6.4. Проверьте настройки

1. Откройте Docker Desktop.
2. Нажмите значок шестерёнки `Settings`.
3. В разделе `General` убедитесь, что выбран `Use the WSL 2 based engine`.
4. Нажмите `Apply`, если изменяли настройку, и дождитесь перезапуска.

На системах, где доступен только подходящий backend, этот переключатель может быть включён автоматически и не
показываться.

Configurator должен работать в режиме Linux containers. Откройте меню Docker через значок кита в системном трее:

- если видно `Switch to Windows containers`, уже выбран правильный режим Linux containers;
- если видно `Switch to Linux containers`, нажмите этот пункт и дождитесь переключения.

Не нужно включать интеграцию с Ubuntu в `Settings → Resources → WSL Integration`: она предназначена для разработки из
терминала Linux и Configurator не требуется.

### 6.5. Автозапуск и место хранения

Автозапуск Docker Desktop можно включить в `Settings → General`. Если он выключен, запускайте Docker Desktop вручную
перед `Start.cmd`.

По умолчанию данные WSL 2 backend хранятся в профиле пользователя, обычно внутри
`C:\Users\<имя>\AppData\Local\Docker\wsl`. Не удаляйте эти файлы вручную. Для переноса используйте только настройки
Docker Desktop `Settings → Resources → Advanced`, если такая возможность доступна в установленной версии.

## 7. Проверка Docker Desktop

Откройте новое окно PowerShell и выполните:

```powershell
docker version
docker compose version
```

У `docker version` должны появиться разделы `Client` и `Server`. Если есть только `Client` и ошибка подключения к
движку, Docker Desktop ещё не запущен или не завершил инициализацию.

Для дополнительной проверки можно загрузить маленький тестовый образ:

```powershell
docker run --rm hello-world
```

Команда требует интернет. Сообщение `Hello from Docker!` означает, что загрузка образа и запуск Linux-контейнера
работают. Эта проверка необязательна для Configurator.

## 8. Первый запуск Configurator

1. Убедитесь, что Docker Desktop запущен и готов.
2. Скачайте Windows-архив Configurator из раздела [официальных выпусков проекта](https://github.com/eltgm/configurator-root/releases).
3. Полностью распакуйте папку `Configurator` в обычное место с правом записи, например в «Документы». Не запускайте
   файлы прямо из ZIP-архива.
4. Откройте распакованную папку.
5. Дважды щёлкните `Start.cmd`.
6. Если Microsoft Defender SmartScreen показывает предупреждение, сначала ещё раз проверьте источник архива и его
   контрольную сумму по руководству локальной поставки. Только после успешной проверки выберите «Подробнее → Выполнить
   в любом случае». Не отключайте антивирус целиком.
7. Не закрывайте открывшееся окно: первый запуск загружает несколько образов и может занять продолжительное время.
8. Дождитесь сообщения о готовности. Браузер откроет <http://127.0.0.1:8080>.

Подробности о контрольных суммах, командах `Stop`, `Update`, `Backup`, `Restore` и удалении находятся в
[руководстве по локальной поставке](../release/LOCAL_DELIVERY.md). Работа с интерфейсом описана в
[руководстве пользователя](USER_GUIDE.md).

Установка завершена, если одновременно выполняются все условия:

- диспетчер задач показывает, что виртуализация включена;
- `wsl --version` выводит версию не ниже 2.1.5;
- `wsl --status` выполняется без ошибки и использует WSL 2;
- Docker Desktop показывает готовность движка и работает с Linux containers;
- `docker version` показывает `Client` и `Server`;
- `docker compose version` выводит номер версии;
- `Start.cmd` открывает Configurator по адресу <http://127.0.0.1:8080>.

## 9. Решение распространённых проблем

После каждого изменения компонентов Windows или BIOS сначала перезагрузите компьютер, затем повторите команды проверки.

### Docker сообщает, что виртуализация отключена

1. Проверьте «Диспетчер задач → Производительность → ЦП → Виртуализация».
2. Если указано «Отключено», повторите настройку BIOS/UEFI по точной инструкции производителя.
3. Если указано «Включено», проверьте компоненты Windows и `wsl --status`.
4. Выполните `systeminfo.exe` и проверьте раздел требований Hyper-V.

### Ошибка `0x80370102`, `HCS_E_HYPERV_NOT_INSTALLED` или `ERROR_NOT_SUPPORTED`

Обычно причина — отключённая виртуализация, отсутствующий компонент WSL 2 или не запущенный гипервизор.

1. Убедитесь, что виртуализация включена в BIOS/UEFI.
2. Убедитесь, что включены «Платформа виртуальной машины» и «Подсистема Windows для Linux».
3. Откройте PowerShell от имени администратора и выполните:

   ```powershell
   bcdedit /set hypervisorlaunchtype auto
   ```

4. Перезагрузите компьютер.
5. Выполните `wsl --status`, затем снова запустите Docker Desktop.

Команда меняет системный параметр загрузки. На управляемом рабочем компьютере выполняйте её только с разрешения
администратора.

### `wsl --version` не показывает версию или Docker требует обновить WSL

Откройте PowerShell и выполните:

```powershell
wsl --update
wsl --shutdown
```

Затем перезапустите Docker Desktop. Если обновление через Store запрещено, используйте официальный WSL MSI или
обратитесь к администратору.

### Docker Desktop долго показывает Starting

1. Подождите несколько минут после первого запуска.
2. Проверьте доступ в интернет и свободное место на диске `C:`.
3. Выполните `wsl --status`.
4. Закройте Docker Desktop через меню значка в трее.
5. Выполните `wsl --shutdown` в PowerShell.
6. Снова запустите Docker Desktop из меню «Пуск».

Не используйте `Reset to factory defaults` как первый способ исправления: сброс удаляет локальные контейнеры, образы,
тома и данные Configurator. Сначала сделайте резервную копию средствами пакета.

По актуальным требованиям Docker в Windows также должна работать системная служба «Сервер» (`LanmanServer`) с типом
запуска «Автоматически». Проверить её можно в PowerShell:

```powershell
Get-Service LanmanServer
```

Если служба отключена на личном компьютере, откройте `Win + R`, выполните `services.msc`, найдите «Сервер», откройте
её свойства, выберите автоматический тип запуска и запустите службу. На рабочем компьютере не меняйте состояние службы
самостоятельно: оно может быть задано политикой безопасности.

### Установщик или WSL просит права администратора

Первое включение WSL 2 и системных компонентов всегда является изменением всего компьютера и требует повышения прав.
Если вы не знаете пароль администратора, остановитесь и обратитесь к владельцу компьютера или IT-службе. Не скачивайте
«обходчики» прав и изменённые установщики.

### Microsoft Store недоступен

Для WSL используйте официальный MSI со страницы [Microsoft/WSL Releases](https://github.com/microsoft/WSL/releases),
как описано в документации Docker. Docker Desktop скачивайте с официального сайта Docker. На рабочем компьютере
блокировка Store часто является частью политики, поэтому сначала согласуйте установку с IT-службой.

### Конфликт с антивирусом, эмулятором Android, VMware или VirtualBox

Некоторые старые версии программ виртуализации, эмуляторы и функции антивирусов могут выключать гипервизор при
загрузке или пытаться единолично использовать аппаратную виртуализацию.

1. Обновите конфликтующую программу и Windows.
2. Проверьте `hypervisorlaunchtype` и виртуализацию после перезагрузки.
3. Изучите официальную инструкцию производителя программы.
4. На рабочем компьютере обратитесь к IT-службе.

Не отключайте антивирус и защитные функции Windows постоянно. Временное отключение или исключение допустимо только
после оценки риска и по официальной инструкции поставщика защиты.

### Компьютер сам является виртуальной машиной

Нужно включить nested virtualization на физическом гипервизоре. Это делает владелец VMware/Hyper-V/VDI-среды. Docker
указывает отдельные лицензионные и технические ограничения для такого сценария; обычная локальная инструкция здесь
недостаточна.

### `docker version` показывает Client, но не Server

1. Откройте Docker Desktop.
2. Дождитесь состояния готовности движка.
3. Проверьте, что выбран WSL 2 backend и Linux containers.
4. Закройте старое окно PowerShell, откройте новое и повторите команду.
5. Если проблема осталась, выполните `wsl --shutdown` и перезапустите Docker Desktop.

### `Start.cmd` сообщает, что Docker недоступен

1. Убедитесь, что Docker Desktop не просто установлен, а запущен.
2. Проверьте `docker version` и `docker compose version` в новом PowerShell.
3. Убедитесь, что у `docker version` есть раздел `Server`.
4. Переключитесь на Linux containers, если выбран режим Windows containers.
5. Повторите `Start.cmd`.

### Образы не загружаются

1. Проверьте обычный доступ в интернет из браузера.
2. Проверьте правильность даты и времени Windows.
3. Если используется VPN или прокси, проверьте настройки `Settings → Resources → Proxies` в Docker Desktop.
4. На рабочей сети уточните у администратора доступ к `ghcr.io`.
5. Не публикуйте лог целиком в открытом обращении, пока не убедитесь, что в нём нет имён пользователей, путей,
   адресов прокси или других конфиденциальных данных.

### Не видно пункта UEFI Firmware Settings

Компьютер может загружаться в устаревшем Legacy-режиме, производитель мог скрыть пункт или модель использует другой
способ входа. Не переключайте самостоятельно Legacy/CSM на UEFI: неправильное изменение может сделать установленную
Windows незагружаемой. Используйте клавишу входа, официальную инструкцию точной модели или помощь специалиста.

### После изменения BIOS Windows просит ключ BitLocker

Введите заранее сохранённый 48-значный ключ восстановления. Если ключа нет, используйте официальную инструкцию
Microsoft по его поиску или обратитесь к администратору организации. Не форматируйте диск и не выключайте TPM или
Secure Boot в попытке убрать запрос.

## 10. Частые вопросы

### Нужно ли устанавливать Ubuntu?

Нет. Docker Desktop не требует отдельного Linux-дистрибутива и работает из Windows. Ubuntu нужна только для отдельных
сценариев разработки.

### Нужно ли включать Hyper-V?

Нет, не для рекомендуемого WSL 2 backend. Hyper-V нужен другому backend и некоторым сценариям Windows containers.

### Подходит ли Windows Home?

Configurator использует Linux-контейнеры, а не Windows containers. Docker отдельно отмечает, что редакции Home могут
работать только с Linux-контейнерами. При этом перед установкой всё равно проверьте актуальный список поддерживаемых
версий и редакций на странице Docker: требования меняются вместе с периодами поддержки Windows.

### Нужен ли аккаунт Docker Hub?

Для загрузки публичных образов Configurator из GitHub Container Registry вход в Docker Hub не требуется. Организация
может установить собственное правило обязательного входа.

### Docker Desktop должен работать постоянно?

Он должен быть запущен во время работы Configurator. После команды `Stop` Docker Desktop можно закрыть, если он не
используется другими программами.

### Можно ли закрыть окно `Start.cmd`?

Закрывайте его только после сообщения об успешном запуске или понятной ошибки. Контейнеры продолжат работать в Docker
Desktop. Для штатной остановки Configurator используйте `Stop.cmd`.

### Где хранятся данные Configurator?

Основные данные находятся в Docker volumes, а резервные копии — в папке `Configurator\backups`. Не удаляйте Docker
Desktop, WSL, volumes или его каталог данных до создания и отдельного сохранения резервной копии.

### Можно ли открыть Configurator с другого компьютера?

Нет. Поддерживается только <http://127.0.0.1:8080> на том же компьютере. В runtime пока нет аутентификации, поэтому
публикация приложения в сеть небезопасна и не поддерживается.
