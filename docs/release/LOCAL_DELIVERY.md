# Локальная поставка Configurator v1

## Поддерживаемый сценарий

Пользователь получает готовый пакет для Windows 10/11 x86-64 или macOS на процессорах Intel и Apple Silicon и
запускает его через Docker Desktop. JDK, Gradle, Node.js, npm и Git не требуются. Приложение доступно только на
<http://127.0.0.1:8080>; серверная установка и публикация порта за пределами локального компьютера не поддерживаются.

Текущая стабильная версия — `v1.2.0`. Пакеты используют общедоступные многоплатформенные образы:

- `ghcr.io/eltgm/configurator-app:stable`;
- `ghcr.io/eltgm/configurator-web:stable`.

Точная версия и дайджесты записаны в `IMAGE_DIGESTS`. `stable` — единственный изменяемый канал обновления; тег
`latest` не публикуется.

На macOS команды `Backup`, `Restore` и обязательное резервное копирование перед `Update` используют внутренний том
Docker. Архив передаётся между контейнерами и компьютером без подключения каталога пакета внутрь контейнера. Готовая
копия сохраняется в `Configurator/backups`; каталог загрузок не нужно добавлять в Docker Desktop File Sharing.

## Установка

1. Установите и запустите актуальный Docker Desktop.
2. Скачайте архив своей операционной системы и файл `SHA256SUMS` из
   [выпуска `v1.2.0`](https://github.com/eltgm/configurator-root/releases/tag/v1.2.0). При расширенной проверке также
   скачайте `IMAGE_DIGESTS`.
3. Проверьте контрольную сумму архива.
4. Полностью распакуйте каталог `Configurator` в место с правом записи. Не запускайте файлы непосредственно из архива.
5. В Windows дважды щёлкните `Start.cmd`. В macOS дважды щёлкните `Start.command`; при первом предупреждении
   Gatekeeper используйте правый щелчок и команду «Открыть».
6. Дождитесь сообщения о готовности и открытия <http://127.0.0.1:8080>.

Проверка в Windows PowerShell:

```powershell
Get-FileHash -Algorithm SHA256 .\configurator-windows-v1.2.0.zip
```

Проверка в macOS:

```bash
shasum -a 256 configurator-macos-v1.2.0.tar.gz
```

## Команды пакета

| Команда   | Назначение                                                                                    |
| --------- | --------------------------------------------------------------------------------------------- |
| `Start`   | Проверяет Docker, загружает образы, запускает приложение и ожидает готовности                 |
| `Stop`    | Останавливает контейнеры без удаления данных                                                  |
| `Update`  | Создаёт обязательную резервную копию, загружает образы канала `stable` и проверяет готовность |
| `Backup`  | Создаёт резервную копию PostgreSQL и MinIO формата v1 с контрольными суммами                  |
| `Restore` | Проверяет копию, создаёт страховочную копию текущего состояния и восстанавливает данные       |

После неудачного `Update` или `Restore` приложение и шлюз намеренно остаются остановленными. Исправьте причину, затем
повторите операцию или восстановите последнюю заведомо рабочую копию. Резервные копии не зашифрованы.

Пошаговая работа с данными и интерфейсом описана в [руководстве пользователя](../user/USER_GUIDE.md).

## Чистая переустановка и удаление

1. При необходимости выполните `Backup` и отдельно скопируйте каталог `backups`.
2. Выполните `Stop`.
3. Для полного сброса откройте терминал в каталоге `Configurator` и выполните:

```bash
docker compose --env-file configurator.env -f compose.yaml down --volumes --remove-orphans
```

4. Удалите распакованный каталог. Для переустановки распакуйте новый архив в пустое место и выполните `Start`.

Сброс безвозвратно удаляет локальные тома. Совместимость резервных копий версий до `v1.0.0` не гарантируется; для них
может потребоваться чистая установка.

## Проверка происхождения

При установленной GitHub CLI подлинность файлов и образов можно проверить командами:

```bash
gh attestation verify configurator-macos-v1.2.0.tar.gz -R eltgm/configurator-root
gh attestation verify oci://ghcr.io/eltgm/configurator-web:1.2.0 -R eltgm/configurator-root
```

## Подготовка поставки владельцем

1. Убедиться, что контрольный список и отчёт выпуска актуальны, непрерывная интеграция прошла, а пакеты GHCR доступны
   без аутентификации.
2. Влить релизный запрос на слияние `develop` в `master`.
3. Создать аннотированный тег на коммите из `master`: `scripts/release/start-release-tag.sh 1.2.0`.
4. Дождаться процесса `Prepare GitHub release`: он повторно запускает все проверки, публикует образы с тегами точной
   версии, коммита и `stable`, создаёт аттестации и черновик выпуска.
5. Проверить анонимную загрузку и установку на чистых Windows и macOS, контрольные суммы и команды
   `Start`, `Stop`, `Update`, `Backup`, `Restore`.
6. Просмотреть заметки и вручную опубликовать черновик выпуска.

Локальная сборка структуры пакетов для проверки:

```bash
scripts/release/build-delivery-packages.sh 1.2.0
```
